3. Core Architecture Rules (Strict Separation of Concerns)
Never mix module responsibilities. BMesh generation in properties.py is strictly forbidden (prevents circular imports).
* __init__.py: Addon metadata, sub-module imports, and central registration loop.
* properties.py: Add-on PropertyGroup classes only.
* generators.py & core.py: 
  - Define functions accepting context and obj. 
  - Init `bm = bmesh.new()`. 
  - Extract properties. 
  - Apply vertex changes securely. 
  - End with `recalc_face_normals`, `to_mesh`, `data.update()`, and `bm.free()`.
* panels/: Append `layout.prop()` to boxes/rows. Pass the literal variable name (omit `text=` unless overriding).
* operators.py: Build action commands here (`LSD_OT_...`).
* Handler Discipline (core.py): Define all app handlers in `core.py`. Register safely: `if handler not in bpy.app.handlers.X: append(handler)`. Enforce `(scene, depsgraph)` signature.
* Propagative Guards: Use `core._prop_update_guard = True` (with try/finally block) during multi-bone editing to prevent recursive loops.

4.1 Timer-based Update Discipline (Mandatory)
Dispatch complex operations (mesh generation, rig updates) triggered from property updates via short-interval timers to avoid "read-only" context errors.
* Pattern: `bpy.app.timers.register(lambda: bpy.ops.prefix.operator_name(), first_interval=0.01)`
* Guard Check: Ensure the update guard is False before registering to prevent infinite loops.

4.2 Debugging and Console Discipline (Mandatory)

* Persistent Shell: Launch via `dev_tool.py` or `.bat` to keep stdout active.
* Informative Errors: Proactively log state changes and calculation results.

5. Procedural Safety Limitations
* Boolean Data Purging: Explicitly delete previous cutter geometry via `bpy.data.objects.remove()` before generating new shapes to prevent boolean z-fighting.
* Real Units: Spatial properties MUST include `unit='LENGTH'` in `bpy.props` for correct Blender 4.5.6+ scaling. Multiply by `obj.dimensions` for size cages.
* Vertex Welding: Always run `bmesh.ops.remove_doubles(bm, verts=bm.verts, dist=0.0001)` before finalizing procedural meshes to close seams.

Rewrote the extraction engine to use Blender's C-level `foreach_get` array API, making the keyframe scanning practically instant. Additionally, added logic to detect if the timeline is currently playing. If it is playing, the operator now safely pauses the internal clock, snaps the frame, and seamlessly resumes playback, allowing the user to snap around the timeline perfectly without having to stop the animation.
- Snap Backwards (Playing) Skip Fix: Added a QoL fix for snapping to the past keyframe while the timeline is playing. Previously, because the timeline constantly moved forward, snapping backwards would instantly push the playhead past the keyframe again, trapping the user in a loop where they could only snap to the exact same keyframe. The "Snap to Past" operator now detects if the timeline is actively playing and automatically skips the *immediate* nearest past keyframe, dropping the user on the *second* past keyframe instead. This allows the user to continuously snap backwards through the animation while it's playing without getting stuck.
- Snap Precision Offset Fix (Off-By-1): NLA math relies on floating-point time data (`strip.frame_start` etc.). Discovered that during snapping and keyframe generation, these float time-offsets were causing precision inaccuracies that would insert keyframes on sub-frames (e.g. `10.999` instead of `11.0`). Added strict `round()` wrappers around all NLA offset calculations in `operators.py` so that keyframes perfectly align with global integer scene frames. Additionally, fully implemented the `strip.scale` interpolation mapping in both operators to ensure mathematically flawless NLA conversions even when users aggressively re-time their layers.
- Keyframe Overwrite Snapping (Float-Drift Fix): Discovered that when using Blender's native keyframing, Tweak Mode perfectly preserves NLA float drift, which causes `bpy.ops.anim.keyframe_insert` to spawn a new keyframe at a subframe (e.g. `5.5`) right next to the original target keyframe (e.g. `5.0`). Rebuilt `LSD_OT_Anim_Keyframe_Entire_Pose` to post-process the F-Curves instantly after keyframing: if a float duplicate is detected, it securely deletes the original keyframe and surgically snaps the newly generated inverse-NLA keyframe down into its place.
- Combine Blending Initialization Fix: The "Combine" layer blend mode was visually acting like "Replace" upon creation, only working after manually switching layers back and forth. Discovered that when a new NLA strip is created via Python and assigned a 'Combine' blend mode, Blender caches its default 'Replace' state in the depsgraph. If `tweakmode_enter` is called immediately afterward without a depsgraph update, Tweak Mode fails to initialize the inverse-NLA math engine. Injected a forced `context.view_layer.update()` inside `invisible_tweakmode_swap` right before Tweak Mode execution, instantly solving the issue.
- Infinite Bounds Restoration (NLA Time Shift Fix): Restored the `frame_start` and `frame_end` to +/- 100,000 (infinite) bounds on all generated NLA strips, and forcibly disabled `use_sync_length`. Previously, the add-on attempted to use localized layer bounds (`use_sync_length = True`), but this caused a severe Blender NLA engine bug where inserting a keyframe outside the action's existing range dynamically resized the action, mathematically dragging the strip's `frame_start` along with it. This caused catastrophic time-desynchronization (keyframes being inserted on the wrong frames in the timeline) and caused layers to "forget" poses because `extrapolation = 'NOTHING'` froze the evaluation outside the strict local bounds. The infinite bounds guarantee the timeline remains perfectly anchored and allows poses to be held across the entire timeline without snapping back.
- Inverse NLA Scale Corruption Fix: Discovered a catastrophic flaw in how the previous infinite bounds hack was applied in Python. Setting `strip.frame_start = -100000` BEFORE setting `strip.action_frame_start = -100000` on an empty action caused Blender's internal engine to divide by zero and permanently destroy the `strip.scale`. Because the scale was corrupted, Blender's Tweak Mode failed to calculate the inverse-NLA mapping. This caused any inserted keyframes to silently reject the NLA math and blindly duplicate the Base Layer's absolute transforms, making it appear as if the poses were being deleted or violently snapping to the first layer's position. Fixed the assignment order globally and explicitly forced `strip.scale = 1.0` during layer initialization, ensuring perfect mathematical Tweak Mode stability.
- Layer Name Collision (Shared Keyframes) Fix: Fixed a critical bug in `LSD_OT_Anim_Layer_Add` where deleted layers would cause the `layer_count` to reuse names (e.g., naming a new layer "Layer 2" when "Layer 2" already existed). This caused Blender to secretly name the internal NLA track "Layer 2.001", which tricked the `anim_core.py` Tweak Mode swapper into activating the old "Layer 2" track instead. Overhauled layer creation to iterate and guarantee strictly unique naming, ensuring brand new layers are truly blank slates.
- NLA Time Shift (Pose Deletion) Fix: Fixed a critical bug in `LSD_OT_Anim_Keyframe_Entire_Pose` where new poses done in animation layers kept getting deleted (teleporting out of sync). When keyframing an empty or localized action, `use_sync_length = True` aggressively changed the action bounds and shifted the `action_frame_start`, which maliciously dragged `frame_start` along with it and destroyed the time sync. The operator now mathematically captures the `orig_offset` before keyframing and surgically restores `strip.frame_start` after insertion, perfectly preserving localized layer bounds while guaranteeing time sync.
- Removed Influence UI & Tweak Mode Toggle: Per user request, the Influence slider and the "Animate Layer (Tweak Mode)" toggle have been completely removed from `ui_animation.py` and `properties.py`. The system has been reverted back to strictly managing the `Blend Mode` property natively, simplifying the UI.
- Layer Muting & Evaluation Logic Fix: Found a severe bug in `anim_core.py` where locking a layer automatically forced its NLA influence to `0.0` and muted its track. Since the Base Layer is locked by default, it was being silently deleted from the Tweak Mode evaluation stack, which caused the rig to snap back to the raw rest-pose when animating on top of it. Separated the `layer.is_locked` checks from the muting logic so that locked layers still evaluate perfectly. Additionally, made the Base Layer automatically muted upon creation as requested.
- Onion Skin Muting Fix: Updated `anim_onion_skin.py` to actively skip F-Curves that are muted, ensuring that ghosts immediately disappear when an animation layer is muted.
- Influence UI Accessibility Fix: Moved the layer Influence slider into the main UI List `LSD_UL_Animation_Layers` instead of keeping it trapped under the active layer properties. Because Blender's Tweak Mode inherently forces the *active* layer's influence to 1.0 (so you can accurately animate it), the slider appeared completely broken when adjusted. Now, users can adjust the influence of *non-active* layers and see the smooth blending results immediately in the viewport.
